### Issue #1: Migrasi Vault ke AES-256-GCM & Backward Compatibility
**Jumlah ide:** 1 ide (Approved)

**Ide utama:**
- [Ide #1]: Self-Describing Storage via Magic Header (`VQF_AESGCM_V1\n`) & Dual Fallback Reader.

**Keputusan:**
- ✅ File karantina baru wajib dienkripsi menggunakan AES-256-GCM dengan CSPRNG nonce 12-byte per file.
- ✅ Menyematkan 14-byte magic header `VQF_AESGCM_V1\n` di disk.
- ✅ Reader pada fungsi `RestoreFile` dan `DownloadFile` otomatis mengenali file baru vs file lama (fallback ke XOR `0xA5`), sehingga zero data loss tanpa skrip batch migration.
- ✅ Master Key diinjeksi ke struct `Vault` dari `crypto.EnsureMasterKey`.

**Next steps:**
